Voice Push-to-Talk 2.1 - Anleitung
==================================

Was ist das?
------------
Taste halten (Standard: F9), sprechen, loslassen. Die Aufnahme geht an den
Whisper-Dienst, der erkannte Text wird in das gerade aktive Fenster eingefuegt.

Voraussetzungen
---------------
* Windows 10 oder 11, 64 Bit
* Ein Mikrofon
* Ein erreichbarer Whisper-Dienst (voreingestellt: http://127.0.0.1:8055)

Wichtig: Die Spracherkennung steckt NICHT in diesem Programm. Es nimmt nur auf
und schickt die Aufnahme an einen Whisper-Dienst - entweder an ein eigenes
Gateway, das zusaetzlich ein LLM zur Nachkorrektur einsetzt, oder an einen
beliebigen OpenAI-kompatiblen Whisper-Server. Laeuft kein solcher Dienst, gibt
es auch keinen Text. Die Adresse steht unter "Einstellungen" und laesst sich
dort mit "Verbindung testen" pruefen.

Python oder .NET muessen NICHT installiert sein - alles Noetige bringt der
Installer mit; die Installation selbst kommt ohne Internet aus.

Installation
------------
VoicePTT-Setup.exe starten und dem Assistenten folgen. Die Installation
erfolgt fuer den angemeldeten Benutzer, es werden keine Adminrechte benoetigt.
Im Assistenten waehlbar:
  * Autostart mit Windows (empfohlen)
  * Desktop-Verknuepfung
  * Programm nach der Installation starten

Eine vorhandene Python-Version (Voice Push-to-Talk 1.x) wird erkannt. Der
Installer bietet an, sie zu entfernen; die alte config.json wird vorher
uebernommen.

Bedienung
---------
Taste halten, sprechen, loslassen. Welche Taste du nimmst, entscheidet, was mit
dem Diktat passiert. Jedes Profil hat einen eigenen Startton, du hoerst also,
in welchem Modus du bist.

  F9  Diktat        Satzzeichen, Gross-/Kleinschreibung, Fuellwoerter raus.
                    Der Wortlaut bleibt.
  F8  Formulieren   Der Text wird frei zu sauberer Prosa umformuliert.
  F7  Roh           Unveraenderte Transkription, keine Nachbearbeitung.
                    Fuer Passwoerter, Code und exakte Zitate.
  F6  Assistent     Das Gesprochene gilt als Auftrag ("schreib eine hoefliche
                    Absage an Herrn Mueller"), eingefuegt wird das Ergebnis.

Ein hoeherer Ton meldet den eingefuegten Text, ein tiefer bedeutet: nichts
erkannt oder Fehler (Details siehe Protokoll).

Tasten, Namen, Anweisungen und Toene sind in den Einstellungen frei aenderbar,
weitere Profile lassen sich anlegen.

Tray-Symbol (Rechtsklick):
  * Weboberflaeche oeffnen (Doppelklick auf das Symbol)
  * Mikrofon auswaehlen
  * Ton-Lautstaerke
  * Taste an das aktive Fenster weitergeben (aus = die Taste wird abgefangen)
  * Automatisch mit Windows starten
  * Einstellungen, Konfigurationsdatei, Protokoll
  * Beenden

Spezialwoerter (Registerkarte "Vokabular")
------------------------------------------
Whisper hoert "Claude" gern als "Cloud" und "Qwen" als "kwen". Dagegen gibt es
eine Tabelle mit drei Spalten:

  Begriff         geht als Hinweis an das LLM - und als Vorgabe an Whisper,
                  aber nur bei endpoint_type=openai. Das eigene Gateway kennt
                  dieses Feld nicht und bekommt es deshalb auch nicht.
  Varianten       werden im fertigen Text hart ersetzt, ohne Ruecksicht auf den
                  Zusammenhang. Nur eintragen, wenn die Falschschreibung nie
                  etwas anderes bedeuten kann ("kwen" ja, "cloud" nein).
  Verwechslungen  nennen dem LLM ein Wort als wahrscheinliche Fehlerkennung.
                  Entschieden wird am Satz: "ich frag mal cloud" wird zu
                  Claude, "die Daten in die cloud" bleibt die Cloud.

Einstellungen
-------------
Alles laesst sich im Dialog "Einstellungen..." aendern. Die Datei liegt unter
  %APPDATA%\VoicePTT\config.json
Das Protokoll liegt unter
  %LOCALAPPDATA%\VoicePTT\client.log

Felder in config.json:
  gateway_url        Adresse des Whisper-Dienstes.
  endpoint_type      "gateway" = eigener Dienst inkl. LLM-Korrektur (Standard)
                     "openai"  = beliebiger Whisper-Server mit OpenAI-kompatibler
                                 Schnittstelle (/v1/audio/transcriptions),
                                 z. B. faster-whisper-server / Speaches.
  model              nur bei endpoint_type=openai: erwarteter Modellname.
  language           optional, z. B. "de"; leer = automatische Erkennung.
  hotkey             Taste des alten Clients. Ab 2.1 stehen die Tasten in
                     "profiles"; dieses Feld wird nur noch mitgeschrieben, damit
                     eine parallel installierte 1.x/2.0-Fassung dieselbe Taste
                     benutzt.
  input_device       null = Systemstandard, sonst Teil des Geraetenamens.
  correct            LLM-Korrektur im Gateway. Ab 2.1 entscheidet das
                     Profil darueber ("correction"); das Feld bleibt fuer eine
                     parallel installierte Altfassung erhalten.
  insert_mode        "paste" (Strg+V) oder "type" (zeichenweise tippen).
  restore_clipboard  Zwischenablage nach dem Einfuegen wiederherstellen.
  samplerate         Aufnahmefrequenz, Standard 16000.
  beep / beep_volume Signaltoene, Lautstaerke 0.0 bis 1.0.
  suppress_hotkey    true = die Taste erreicht das aktive Fenster nicht mehr.
  min_seconds        kuerzere Aufnahmen werden verworfen.
  llm_url            OpenAI-kompatibler Chat-Endpunkt fuer die Nachbearbeitung,
                     z. B. http://192.168.178.34:8082/v1
  llm_model          Modellname, den dieser Endpunkt erwartet. Erst wenn
                     Adresse UND Modell gefuellt sind, arbeitet die
                     Nachbearbeitung im Client; sonst korrigiert das Gateway.
  llm_temperature    Vorgabe 0 - gleiche Eingabe, gleiche Ausgabe.
  llm_timeout_seconds  Frist je Anfrage, Vorgabe 120.
  send_vocabulary_to_whisper
                     Begriffe als "prompt" an Whisper schicken
                     (nur endpoint_type=openai).
  llm_extra          wird unveraendert in die Anfrage gemischt (serverspezifische
                     Schalter); ein Feld mit null entfernt einen Schluessel.
  profiles           Taste, Name, correction (llm/gateway/none), Anweisung,
                     thinking, replacements, beep_hz.
  vocabulary         term, variants, confusions, active.
  log_prompts        schreibt den fertigen Systemprompt ins Protokoll.

Nachbearbeitung durch das Sprachmodell
--------------------------------------
Ohne eingetragene LLM-Adresse verhaelt sich das Programm wie frueher: Profile
mit der Korrektur "llm" lassen dann das Gateway korrigieren. Antwortet das
Sprachmodell nicht oder zu langsam, wird der unveraenderte Rohtext eingefuegt -
ein Diktat geht nie verloren.

Qwen3 und verwandte Modelle denken vor jeder Antwort sichtbar nach, was eine
Korrektur von unter einer Sekunde auf rund 30 Sekunden streckt. VoicePTT
schaltet das ab; der Schalter "Denken" im Profil stellt es bei Bedarf wieder an
- bei freien Formulierungen lohnt sich das manchmal.

Beispiel fuer ein lokales Whisper auf demselben Rechner:
  "gateway_url": "http://127.0.0.1:8000",
  "endpoint_type": "openai",
  "model": "Systran/faster-whisper-small",
  "language": "de"

Deinstallation
--------------
Windows-Einstellungen -> Apps -> "Voice Push-to-Talk" -> Deinstallieren.
Auf Wunsch werden dabei auch Konfiguration und Protokoll entfernt.

Problemloesung
--------------
Kein Text wird eingefuegt
  Protokoll oeffnen (Tray-Menue). Dort steht, ob die Aufnahme lief und was der
  Dienst geantwortet hat.
Taste reagiert nicht
  Laeuft im Vordergrund ein Programm mit Adminrechten (z. B. Task-Manager),
  erhaelt ein normales Programm keine Tastendruecke. Voice Push-to-Talk dann
  ebenfalls als Administrator starten.
Falsches Mikrofon
  Tray-Menue -> Mikrofon. "Standard (automatisch)" nutzt das Windows-Standardgeraet.
Dienst nicht erreichbar
  Einstellungen -> "Verbindung testen".
